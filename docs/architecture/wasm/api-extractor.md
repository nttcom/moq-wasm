# ADR: API Extractor reports for the browser SDK

## Status
Accepted

## Date
2026-11-13

## Context
A change to `moq-wasm` can change what the package exports (a renamed option, a widened return type) without any
line in the diff saying so: the declarations are generated by `tsc` into `types/`, which is not committed. A
reviewer cannot tell from a pull request whether the public API changed.

## Decision
Add **`@microsoft/api-extractor`** as a devDependency of `moq-wasm`. For each entry point in `exports` that has
types (`.`, `./media`, `./recording`), it reads the built `types/<entry>/index.d.ts` and writes
`crates/wasm/js/api/<entry>.api.md`, the exported declarations with their signatures. The reports are committed.
The `sdk-package` CI job builds the package and runs `npm run api:check`, which fails when a report differs from
the declarations; `npm run api:update` rewrites them.

Release tags and TSDoc syntax are not checked (the SDK uses `///` comments and no release tags), so the reports
only list declarations and the types they reference but do not export (`ae-forgotten-export`).

## Consequences

### Positive
- A pull request that changes the public API changes a report file, and that diff is the API change.
- Internal modules can change freely: only declarations reachable from an entry point are reported.

### Negative
- API Extractor reports one entry point per run, so there are three configs and three reports.
- It analyzes with its own TypeScript (6.x) and cannot report `typeof import('...')`, so the SDK writes the wasm
  module type as `typeof` a namespace import.
- A type that an export references but the entry point does not export is reported by name only, so a change
  inside it does not show.

### Neutral
- The reports are excluded from Prettier (`crates/wasm/js/.prettierignore`), since the check compares them byte
  for byte.

## Alternatives Considered

### Committing the concatenated `types/**/*.d.ts`
Needs no dependency, but includes every internal module, so refactors that leave the API alone would still
change the report.

### dts-bundle-generator / rollup-plugin-dts
They bundle declarations for publishing rather than report them, and neither is in the workspace.
